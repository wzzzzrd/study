# Учебный проект: Интеграция SAST в CI/CD пайплайн

Репозиторий содержит демонстрационное Python-приложение и конфигурационные файлы для построения защищенного конвейера непрерывной интеграции (CI/CD) на базе **Jenkins** и платформы контроля качества кода **SonarQube**.

## 🎯 Цели и задачи проекта

1.  **Освоение принципов DevSecOps:** Внедрение этапов статического анализа безопасности (SAST) непосредственно в процесс сборки проекта.
2.  **Защита инфраструктуры:** Обеспечение контроля качества кода с помощью жестких критериев остановки сборки (Quality Gate).
3.  **Устранение уязвимостей:** Практическая демонстрация замены небезопасных конструкций на криптостойкие и защищенные аналоги (исправление потенциальных RCE, обхода авторизации и слабых алгоритмов хеширования).

## 🛠 Стек технологий и инструментов

*   **Язык разработки:** Python 3 (тестирование через `pytest` и `pytest-cov`)
*   **Среда автоматизации:** Jenkins (Declarative Pipeline)
*   **Статический анализатор:** SonarQube + Sonar Scanner
*   **База данных:** SQLite (для демонстрационного слоя данных)

## 📁 Структура репозитория

*   `app.py` — Основной модуль приложения, содержащий безопасные реализации функций работы с ОС, сетью, криптографией и сессиями.
*   `test_app.py` — Модульные тесты для проверки корректности бизнес-логики.
*   `Jenkinsfile` — Декларативный сценарий сборки и анализа для сервера Jenkins.
*   `sonar-project.properties` — Конфигурационный файл параметров сканирования для Sonar Scanner.
*   `requirements.txt` — Список зависимостей среды тестирования (`pytest`, `pytest-cov`).

## 🔒 Реализованные меры безопасности (Fixes)

В ходе аудита исходного кода приложения были устранены критические дефекты безопасности и применены следующие защитные механизмы (`app.py`):

1.  **Защита от SQL-инъекций:** Использование строго параметризованных запросов к СУБД вместо конкатенации строк (`conn.execute("...", (username,))`).
2.  **Предотвращение Remote Code Execution (RCE):**
    *   Вызов системных утилит через `subprocess.run` в виде списка аргументов с явным отключением выполнения через системную оболочку (`shell=False`).
    *   Валидация входящих хостов по белому списку разрешенных символов перед отправкой в системные команды.
3.  **Криптостойкое хеширование:** Замена небезопасных MD5/SHA1 на ресурсоемкий алгоритм `scrypt` с использованием случайной криптографической соли (`os.urandom`).
4.  **Безопасное управление сессиями и конфигурацией:**
    *   Отказ от потенциально опасной десериализации через `pickle` в пользу безопасного формата `json`.
    *   Использование функции `yaml.safe_load` для парсинга конфигурационных файлов, исключающей выполнение произвольного кода.
    *   Генерация токенов сброса пароля через криптографически стойкий модуль `secrets`.
5.  **Безопасность сетевого взаимодействия:** Использование библиотеки `requests` с обязательной проверкой TLS-сертификатов и жестко заданными таймаутами для предотвращения зависания потоков сборки.

## 🔄 Описание CI/CD конвейера

Пайплайн описан в `Jenkinsfile` и состоит из следующих последовательных стадий:

1.  **Checkout:** Клонирование исходного кода из системы контроля версий (Git).
2.  **Setup:** Инициализация изолированного виртуального окружения `venv` и установка необходимых зависимостей из `requirements.txt`.
3.  **Build:** Проверка синтаксической корректности кода путем компиляции скриптов в байт-код (`py_compile`).
4.  **Test:** Запуск модульных тестов с генерацией JUnit-отчетов и выгрузкой XML-карты покрытия кода тестами (Code Coverage).
5.  **SonarQube Analysis:** Статическое сканирование кодовой базы и отправка результатов на сервер SonarQube.
6.  **Quality Gate:** Блокирующий этап (таймаут 5 минут), который ожидает ответа от вебхука SonarQube. Если проект не проходит установленные метрики качества (например, наличие уязвимостей или низкое покрытие тестами), сборка принудительно прерывается со статусом `FAILURE`.

## ⚙️ Настройка интеграции

Для успешного выполнения пайплайна в окружении Jenkins должны быть предварительно настроены:

1.  **SonarScanner Tool:** Глобальная утилита с именем `sonar-scanner`.
2.  **SonarQube Server:** Интеграция в системных настройках Jenkins с именем сервера `sonarqube` для автоматической проброски переменных окружения `withSonarQubeEnv`.
3.  **Переменные среды:** Секрет `DB_PASSWORD` должен быть безопасно передан в контейнер/раннер через механизмы Credentials.
